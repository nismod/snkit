# The snkit kernel

The part of [snkit](https://github.com/nismod/snkit) that does the heavy work, in Rust.

`snkit` finds what to change in a network by matching geometry, then applies exact edits
to topology. The kernel sees only flat arrays - coordinates, offsets, positions - and no
tables, attributes or geometry objects. It is compiled into the Python package as
`snkit._native`; the Python code around it turns tables into arrays, calls the kernel, and
moves attributes by the positions it returns.

| Function | Does |
| --- | --- |
| `components`, `group_index` | Labels connected components (union-find), and numbers them. |
| `line_measures`, `locate` | Distances along lines; the place a given distance along. |
| `split` | Cuts edges at places along them, in one pass. |
| `sync_ends`, `extend_ends` | Keeps edge ends exactly on their nodes. |
| `segment_crossings` | Finds where line segments meet, tile by tile and in parallel, deciding with exact predicates. |
| `point_pairs`, `nearest_points` | Finds points near each other. |
| `points_near_lines`, `nearest_lines` | Finds lines near each point, and the nearest place on them. |
| `read_geometry`, `geometry_bounds` | Reads geometry from a stream of Arrow record batches, as WKB or native GeoArrow. |
| `tile_owners`, `tile_reaches` | Says which tile of a tiling each place is in, and which tiles each box reaches into. |

It has its own spatial index (a static R-tree packed along a Hilbert curve, in `rtree.rs`)
and depends only on `rayon`, `robust` and `arrow`. Tables of geometry come in through the
Arrow C stream interface, so a caller in any language that has Arrow can use the kernel
without geometry code of its own.

## Building

Installing `snkit` from source builds the kernel, which needs a Rust toolchain
(<https://rustup.rs>):

    pip install -e .[dev]

Run that again after changing Rust code. The kernel's own tests need no Python:

    cd kernel
    cargo test --release

## Use from Rust

```rust
use snkit_kernel::crossings::segment_crossings;

// two lines, as interleaved coordinates and offsets
let coords = [0.0, 0.0, 2.0, 2.0, 0.0, 2.0, 2.0, 0.0];
let found = segment_crossings(&coords, &[0, 2, 4], false);
assert_eq!(found.xy, vec![1.0, 1.0]);
```

## Releases

`snkit` is no longer a pure-Python package, so a release needs a wheel for each platform.
`workflows/package.yml` in this directory is a GitHub Actions workflow that builds them,
as generated by `maturin generate-ci github`. It is meant to replace
`.github/workflows/package.yml`, and has not been run. The package version is the
`version` in `Cargo.toml`.

## Memory

Functions state their working memory in their documentation. In outline, for the whole
input: `components` 4 bytes per node; `split` writes its output once; `segment_crossings`
8 bytes per segment plus a small index per tile per thread; `point_pairs` 20 bytes per
point; the nearest searches 36 bytes per segment. See section 8 of
`docs/source/design.md` for measurements and the plan for networks too large for memory.
